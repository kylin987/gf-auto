# 闲鱼客户端多店铺实例设计

## 目标

将客户端从“一个进程默认使用第一个授权店铺”调整为“一个客户端管理多个独立店铺实例”。每个实例有独立的闲鱼登录态、Chrome Profile、网关连接、事件日志和运行状态，避免不同店铺的消息或订单归属混淆。

## 店铺绑定

网关登录返回授权店铺列表，店铺字段至少包括：`id`、`storeName`、`sellerNick`、`platformShopId`。

实例启动前读取对应 Cookie 的闲鱼 `userId`，必须与已选择店铺的 `platformShopId` 完全一致：

- 匹配：启动闲鱼消息连接与网关 WS，并在所有事件中携带该 `storeId`。
- 无匹配：拒绝启动和上报，界面展示明确的店铺不一致原因。
- Cookie 失效：只停止当前实例，其他实例继续运行。

历史单店 `cookies.json` 自动迁移为默认实例，确保已运行用户升级后不需要重新配置。

## 数据与进程模型

客户端配置根目录为 `%LOCALAPPDATA%\\yhs-fish-plugin`：

```text
instances.json
instances/
  <instance-id>/
    cookies.json
    chrome-profile/
    log/
```

每个实例创建一个 `XianyuLive` 运行单元，单独维护闲鱼长连接、网关客户端、停止信号和本地 HTTP 端口。端口按实例稳定分配，避免本地任务回调冲突。

## 界面

采用“运营工作台”布局：

- 概览页的首要信息为当前选中的店铺实例及其 Chrome 闲鱼 ID。
- 展示网关连接、闲鱼连接、今日消息、成功上报、订单事件、待关注异常。
- 实时事件按买家消息、网关任务、订单、异常分类，包含店铺名、时间和结果。
- 店铺实例页支持新增、启停、删除和查看绑定状态。
- 登录子账号、客户端版本及在线更新保持可见，但不抢占运行状态的视觉层级。

## 失败隔离与日志

实例的登录、网络或任务失败不影响其他实例。所有可见日志都带实例 ID、后台店铺名、闲鱼 ID、事件 ID 或任务 ID；Cookie、Token 与原始敏感报文不显示到界面。

## 更新与验证

继续使用 OSS `latest.json` 与 NSIS 安装包。升级时保留 LocalAppData 内的实例数据。

最低验证覆盖：

- 单店旧 Cookie 自动迁移。
- 多个实例的 Cookie 路径、端口、日志路径相互隔离。
- Chrome `userId` 与 `platformShopId` 匹配 / 不匹配场景。
- 每个实例的消息上报携带自己的 `storeId`。
- 一个实例停止或连接失败时，其他实例持续工作。
